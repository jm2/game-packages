# Windows packages (GooGet)

The repo also builds Windows packages in GooGet's `.goo` format, published
by crossdock next to the Arch and Fedora repos (`goo/linux-packages/`).
Clients:

```
# The repo is plain http on the LAN; googet 2.11+ needs this to use it:
Add-Content C:\ProgramData\GooGet\googet.conf 'allowunsafeurl: true'
googet addrepo linux-packages http://<crossdock host>:8080/goo/linux-packages
googet install quake3e quake3-data-steam quake3-pointrelease-data
```

GooGet has no repo signatures; the index pins each package's SHA-256. Use
it on a trusted LAN or behind HTTPS. googet (2.11 and later) ignores plain
`http://` repos unless `allowunsafeurl: true` is in
`C:\ProgramData\GooGet\googet.conf`. crossdock serves no TLS itself; HTTPS
would be a TLS proxy (nginx/Caddy) in front of it, which needs a certificate
the clients trust.

## What a Windows package is

| Linux package | Windows package |
|---|---|
| `*-wine-steam`, `*-wine-gog` | Same game files installed natively, named without `-wine` (`wreckfest-wine-gog` -> `wreckfest-gog`), with the same Goldberg / XLiveLessNess files copied in, Start Menu shortcuts per launcher variant and inbound firewall rules for the game executables. No Wine, gamelaunch or prefix. |
| `*-data-*` | Same data, same name and `provides`. |
| Engines (quake3e, ...) | Upstream's Windows release, from a hand-written `windows/goo.toml`. |
| `native-*` (Linux depots) | Planned: the Windows depot of the same game. |
| Linux plumbing (gamelaunch, wine-ipv6only, lib32-*, ...) | None. |

Everything installs under `C:\Program Files\Games\<dir>`, where `<dir>` is
the first component of the Linux target below `/opt`, `/usr/share/games` or
`/usr/share` (`/opt/quake3` and `/usr/share/games/quake2` become
`...\Games\quake3` and `...\Games\quake2`), so data packages land next to
their engine. Not `C:\Games`: a new directory in the root of C: lets every
authenticated user modify everything in it (inherited from C:\'s ACL), and
fixing that from an install script is too late (googet copies first) and can
be defeated by pre-created directories or junctions. The Start Menu
shortcuts and firewall rules are for all users, so their targets must not be
user-writable.

Games that write next to their binaries (`writable` in package.toml, XLLN
games) get Users modify rights on their directory, except on the
executables and DLLs installed there, so a standard user can't replace a
program another user runs; they can still add files, including DLLs a game
might load, so mark only games that need it. Quake3e keeps each user's
settings in `%APPDATA%\Quake3` (`+set fs_homepath` in its shortcuts)
instead. Firewall rules allow the local subnet only, on every profile
(home networks are often classed as Public). Removing every package leaves an empty
`C:\Program Files\Games`: googet doesn't track parent directories it
creates, and uninstall scripts run before the files are removed.

## Files

- `<pkg>/windows/goo.toml`: the manifest (format in `tools/goopack.py`).
  Generated by `tools/gen.py` for wine-steam, wine-gog and data-* families;
  hand-written for engines. `[goo] disabled = true` in package.toml turns a
  generated one off; `[goo] deps = [...]` adds dependencies.
  `[goo] description` and `release_notes` replace the Linux text,
  `[goo] release_offset` bumps only the Windows release, and
  `[[goo.shortcut]]` adds Start Menu entries (a data package's shortcut to
  its engine). A shortcut with `requires = "<stage path>"` is only created
  when that file is installed, so an engine and its data (separate
  packages) both carry it and whichever comes second creates it; quake3e
  and the quake3 data packages do this for Quake III and Team Arena.
  Install scripts reconcile (create or delete), because a googet upgrade
  runs only the new version's install script, never the old uninstall.
- `tools/goo-build <pkgdir> [out]`: downloads `[[source]]` files, runs the
  `[stage]` script (generated packages: `build.sh prepare` + `install` in a
  Fedora container with gbe-fork-bin / xlln-bin from `$OUT`, links followed)
  and packs the result with `tools/goopack.py`. Store data comes from the
  same `PT_CACHE` as the Linux builds (`tools/fetch-steam`, `tools/fetch-gog`).
- `tools/promote` moves `.goo` files into crossdock's incoming directory
  like the other formats.
- `tools/build-all --formats arch,fedora,goo --goo-dest <incoming>/goo` builds
  them with the Linux packages, sharing each download. A goo-only run needs
  Fedora builds of gbe-fork-bin and xlln-bin in `$OUT` already.

Versions become googet's `X.Y.Z@release` (`tools/goopack.py goo_version`):
`1.0o` -> `1.0.15`, Steam `1.27.b16986367` -> `1.27.16986367`.

googet downloads a package to its cache and extracts it before copying the
files, so a client needs about two and a half times a package's size free
while it installs (measured with quake3e and the point release paks). The
extracted copy is deleted afterwards; the cached .goo stays until the
package is removed (`googet clean` empties the cache).

## Tested (2026-11-08, Windows 11, googet 3.4.1 built from source)

quake3-pointrelease-data and quake3e installed, verified and removed cleanly:
files, Start Menu shortcuts (`%APPDATA%` in shortcut arguments is expanded
by the shell), firewall rules, ACLs inherited from Program Files, and an
"Apps & features" entry for packages with an install script. Client notes:

- After googet's installer sets `GooGetRoot` machine-wide, open a new shell
  (or pass `-root`): older shells fail with `The environment variable
  "GooGetRoot" is not defined`.
- `googet installed` exits 1 when nothing is installed.
- googet 3.4.1 can't install a dependency that only a `Provides` satisfies
  (`install/install.go` listDeps resolves the provider but keeps the
  virtual name: `no match found for package quake3-data.noarch...`). So
  Windows packages depend on real package names only (`tools/gen.py`
  checks), and quake3e has no data dependency: install
  `quake3-data-steam` or `quake3-data-gog` with it.
