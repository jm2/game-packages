## 2. Runtime bugs

### Age of Empires / Mythology (aoe2-de, aoe3-de, aom-retold)
- `ColdClientLoader.ini` points at `Z:\opt\aoe2-de-wine-steam\...`, but the
  game is installed to `/opt/aoe2-de`. The loader exe isn't installed or
  launched anyway, so the file is dead config.
- `find_interfaces.sh` doesn't exist in gbe_fork (its tool is
  `tools/generate_interfaces/generate_interfaces_x64`), so
  `steam_interfaces.txt` is never generated. Even if it were, the PKGBUILD
  copies the emulator DLL over the original first, so it would scan the
  emulator instead of the original (the original must be scanned).
- `find "$srcdir" -name steam_api64.dll -quit` picks whichever DLL `find` hits
  first: `regular/x64`, `experimental/x64`, or the game's own. The
  `find -name server/launcher` calls have the same problem.
- `configs.user.ini` sets `local_save_path=saves`, which is relative to the
  DLL, i.e. `/opt/aoe2-de/saves`. That isn't writable by the user. Remove it,
  and gbe_fork defaults to `$XDG_DATA_HOME/GSE Saves`.
- The ageLANServer launcher runs out of read-only `/opt/.../agelanserver`. It
  writes certs/config under `resources/` at runtime (*verify*), so it needs a
  per-user writable copy.
- Pins are stale: ageLANServer 1.12.1 (current 1.15.6), Companion 1.3.0.0
  (current 1.5.0.0).
- The Maintainer line is still the `Your Name <your.email@example.com>` placeholder.

### Wine launchers (all `*-wine-*`)
- The prefix lives in `~/.<game>/wine` (not XDG). The first-run guard is
  `[ ! -d ~/.<game> ]`, but `mkdir` runs before `wineboot`/`setup_dxvk`, so a
  failed first run leaves a half-built prefix that is never repaired.
- `setup_dxvk` only exists in the AUR `dxvk-bin` package. Fedora's
  `wine-dxvk` (alternatives-based) and Debian's `dxvk` don't provide it, so
  none of these launchers port to RPM/Deb as written.
- `--symlink` points into `/usr/share/dxvk`. If dxvk is uninstalled or moved,
  the d3d DLLs silently become dangling links.
- `winetricks openal` / `winetricks -q mfc140` run on first launch: network
  access, interactive, and unpinned. grid-wine-gog also depends on
  lib32-openal, which is redundant.
- No `exec`, `"$@"` isn't forwarded (except AoE), and there's no `WINEARCH`
  or wine version pinning.
- wreckfest-wine-gog `cd`s into `/opt/wreckfest`, but the GOG data is
  installed to `/opt/wreckfest-gog`, so **it can never launch**. It also
  shares the prefix `~/.wreckfest` with the Steam variant.
- wreckfest-gog-dlc1/2 install to `/opt/wreckfest_season_pass_N-gog`, which
  the game never reads.
- wreckfest2 uses `umu-run` with no `GAMEID`, so no protonfixes are applied.
  It also still uses the 2023 Mr_Goldberg build.
- codghosts `-h` prints "codaw". codwaw's `-h` text doesn't match its flags.
- doom2016, warcraft3, and wreckfest2 skip dxvk. That's fine for Vulkan or
  OpenGL games, but it's undocumented.

### Security
- `chmod o+w /opt/<game>` (cod4, codaw, codghosts, codmw2, codwaw, codww2),
  `chmod 777` (broforce-gog/steam), and `chmod 666 *.ini` (ut-goty) make game
  directories world-writable. Any local user can plant a DLL/.so that another
  user's game then loads. These need a per-user writable overlay instead
  (see §3.2).

### Native / data packages
- ut2004-gog launcher: `[ -f "/opt/ut2004/__support/app/System/" ]` tests a
  directory with `-f`, so it's always false. The desktop file's
  `Exec=/opt/ut2004/Scripts/ut2004` bypasses `/usr/bin`, and the script is
  installed twice.
- unreal-tournament.sh passes `-homedir` with no value (*verify* against 469e).
- serioussam2-steam runs an interactive `steamcmd` login inside `package()`
  (under fakeroot) and uses md5sums.
- dirt4-steam, dirtrally-steam, gridautosport-steam (Feral ports) depend on
  `openssl-1.0`, `gconf`, `libidn11`, `librtmp0`, all AUR-only legacy libraries.
- doom3bfg-data-gog installs to `/opt/doom3bfg`, but steam (after the
  backport) installs to `/usr/share/games/doom3bfg`. Align GOG to match.
- doom3xp-data-steam (the Doom 3 expansion) exists, but there is no Doom 3
  base data package.
- eliteforce-data-gog installs into the engine's directory
  (`/opt/lilium-voyager/baseEF`).
- geysermc.service runs as root with `WorkingDirectory=/usr/share/geysermc`
  (read-only). Geyser writes logs, cache, and keys to its working directory.
  Use `DynamicUser=yes` + `StateDirectory=geysermc`.
- owntone.install uses `$pkgdir` (empty at install time) and calls
  useradd/groupadd directly. Replace with `sysusers.d` + `tmpfiles.d`.
- netatalk `*.service` files use `ExecStart=/usr/sbin/...` while configure
  uses `--sbindir=/usr/bin`. That works on Arch and on Fedora ≥42 (merged
  sbin), but breaks on Debian.
- quake2rtx (source): 1.7.0 vs -bin 1.8.1. It lists `vulkan-headers` as a
  runtime dependency (both variants), uses `git checkout` in prepare instead
  of `#tag=`, and runs cmake without a build type. Upstream was **archived
  2025-12-11**, so 1.8.1 is final.

## 3. Cross-cutting proposals

### 3.1 New shared package: `gbe-fork-bin` (replaces all hardcoded Goldberg)

gbe_fork (Detanup01) is the most active Goldberg fork: last push 2026-10-30,
2.8k stars, releases every 1–3 weeks. The original Mr_Goldberg GitLab is
frozen, and the other forks checked are gone. License: LGPL-3.0.

Pin: **release-2026_09_27** using the **vs26** Windows build
(`emu-win-release-vs26.7z`, sha256 `417b7d34…c243`) plus `emu-linux-release.tar.bz2`
(sha256 `f3e08366…b9c7`). The release notes say "LINUX ARTIFACTS ARE ARM!!!".
The ELF headers checked here show `x64`=x86-64, `x86`=i386, `ARM64`=aarch64,
and the x64 BuildID changed from 09_16_2, so the warning looks stale.
*Verify* with a single game launch before bumping all packages.

Proposed layout:
```
/usr/lib/gbe-fork/win/{x86,x64}/steam_api{,64}.dll            # regular
/usr/lib/gbe-fork/win-experimental/{x86,x64}/...              # experimental
/usr/lib/gbe-fork/win-steamclient/...                          # ColdClientLoader set
/usr/lib/gbe-fork/linux/{x86,x64,arm64}/libsteam_api.so       # regular
/usr/lib/gbe-fork/linux-experimental/...
/usr/bin/gbe-generate-interfaces                               # wrapper, picks arch
/usr/share/doc/gbe-fork/steam_settings.EXAMPLE/
```
Game packages would:
1. `makedepends+=(gbe-fork-bin)`. At build time, run
   `gbe-generate-interfaces <original dll>` into `steam_settings/steam_interfaces.txt`.
2. Either **symlink** the game's `steam_api64.dll` to
   `/usr/lib/gbe-fork/win/x64/steam_api64.dll` (`depends=(gbe-fork-bin)`, so
   emulator updates reach every game without rebuilding multi-GB packages),
   or **copy** at build time (pinned per game). Recommendation: symlink, with
   `gbe-fork-bin>=<tested>` lower bounds.
3. Ship `steam_settings/` (appid, configs, achievements) read-only in `/opt`.
   Saves go to `$XDG_DATA_HOME/GSE Saves` (no `local_save_path`).

Packages affected: 21 (3 already on gbe_fork, 18 on Mr_Goldberg builds `a24a9c26`/`475342f0`).

### 3.2 New shared package: a wine/umu game launcher (fixes the config dir / dxvk mess)

One small shell library plus a declarative per-game file replaces 25+
copy-pasted launchers:

```sh
# /usr/share/<launcher>/games/dirt3.conf
GAME_ID=dirt3
GAME_DIR=/opt/dirt3
GAME_EXE=dirt3_game.exe
DXVK=1
UMU_GAMEID=umu-321040
WINE_PREREQS=openal          # run from the game's bundled redist, not winetricks
WRITABLE=overlay             # per-user symlink farm instead of chmod o+w
VARIANTS="-l:Wreckfest.exe -m:Wreckfest_x64.exe"   # replaces getopts blocks
```

Behaviour:
- Prefix in `${XDG_DATA_HOME:-~/.local/share}/<launcher>/<id>/prefix`. On
  first run, migrate (move, plus a back-compat symlink) an existing
  `~/.<id>/wine` so nobody loses saves.
- Setup is stamped: `.setup-done` is written only after `wineboot` + dxvk +
  prereqs all succeed, so a failed run is retried next launch.
- Backend: `umu` (Proton, bundles DXVK and VKD3D-Proton, consistent on every
  distro) or `wine` (system wine + DXVK). The default is your choice (see
  questions); override per run with `GAME_RUNNER=wine|umu`.
- System-wine DXVK is resolved **at launch** from whatever the distro ships:
  Arch `dxvk-bin` (`/usr/share/dxvk`), Debian `dxvk`, Fedora `wine-dxvk`
  (already wired in via alternatives, nothing to do). It is set with
  `WINEDLLOVERRIDES` in the environment rather than registry edits, and
  re-linked every launch, so it self-heals when dxvk moves or upgrades. No
  more `setup_dxvk`.
- `WRITABLE=overlay`: builds `$XDG_DATA_HOME/<launcher>/<id>/game/` as a
  symlink farm of `/opt/<id>` and runs from it, so writes land per-user. This
  replaces every `chmod o+w`/`777`/`666`. The same helper works for native
  games (broforce, UT GOTY ini files).
- Always `exec`, always forward `"$@"`.

Distro availability (verified 2026-11-02): umu-launcher 1.4.4 is in Arch
`multilib`. It is **not** in Fedora or Debian archives; upstream publishes
`.rpm` (fc43/fc44) and `.deb` (debian-12/13, ubuntu noble/resolute). DXVK:
Debian `dxvk` 3.1.1 (sid) / 2.6 (trixie), Fedora `wine-dxvk` 2.7.1 (rawhide),
Arch: AUR only.

### 3.3 Getting game data without an interactive `read`

`printf/read steam_username` in `prepare()` breaks `makepkg --noconfirm`,
any CI, `rpmbuild` under mock, and `sbuild`/`pbuilder` (no tty, no network).
Proposal: `tools/fetch-steam <appid> [depot…]` and `tools/fetch-gog <slug>`
(lgogdownloader), driven by `STEAM_USER`/config, which populate a cache under
`${TMPDIR:-/var/tmp}/linux-packages-cache/<pkg>/`. PKGBUILD `prepare()`, RPM
`%prep`, and `debian/rules` all consume that directory, falling back to the
interactive prompt only on a tty. This also fixes the aoe2 `download_depot`
path guessing (pass an explicit install dir per depot), and lets `pkgver` be
the real Steam buildid instead of `1.0`.

Also standardize the GOG `DLAGENTS` hack and add a real `hib://` handler
that prints instructions.

### 3.4 RPM / Deb constraints worth knowing up front

- **Not distributable.** These packages contain proprietary game data,
  unpacked/patched executables (Blur, DOOM 2016, CoD WaW, DiRT Showdown),
  and Steam emulators, so Copr/OBS/PPA/Launchpad are out (as you already
  concluded for openq4). The specs/debian dirs are for local
  `rpmbuild`/`dpkg-buildpackage` only.
- **Debian package size ceiling.** The `.deb` ar member header has a
  10-digit size field, so `data.tar` maxes out at ~9.3 GiB. CoD WWII, DOOM
  2016, GRID 2019, DiRT Rally 2.0, AoE2 DE, and AoM Retold exceed that. Those
  need either a split (`<game>-data-1..N`) or a deb that installs only
  launcher + metadata and fetches data in a post-install helper. RPM ≥4.6
  and pacman have no such limit.
- **Compression time.** Use `%global _binary_payload w3.zstdio` (as openq4
  does) everywhere, `-Zzstd -z1` for dpkg-deb, and consider
  `PKGEXT='.pkg.tar'` for the huge Arch data packages.
- **Debian `game-data-packager`** (contrib) already produces data .debs for
  many of the same titles (Quake 2/3/4, Doom 3, UT99, UT2004, Elite Force,
  ETQW; *verify* the exact list). For Debian, either align install paths
  with it or document it as the preferred route for id-tech/Unreal data.
- lib32 dependencies map to `foo(x86-32)` on Fedora and `foo:i386`
  (multiarch, needs `dpkg --add-architecture i386`) on Debian.
- Non-game packages: before adding specs, check whether Fedora/Debian
  already ship them (netatalk 4.x, grip, owntone) and skip the duplicates.
  xf86miscproto has no RPM/Deb use (libXxf86misc was dropped there).

### 3.5 Repo structure, tooling, hygiene

- **Single source of truth.** 80 packages × 3 formats is 240 hand-maintained
  build files, and §0/§1 show how quickly even one format drifts.
  Recommendation: a small per-package `package.toml` (name, version,
  sources, appid, exe, deps per distro, launcher conf) plus templates per
  family (wine-steam, wine-gog, native-steam, data-steam, data-gog) that
  generate PKGBUILD + `.spec` + `debian/`. Bespoke packages (netatalk,
  owntone, tributary, openq4, UT, cro-mag) stay hand-written.
- **`.gitignore` will swallow the new work.** `/*/*/` ignores every package
  subdirectory, including `debian/`. `*.txt` ignores `steam_appid.txt` and
  `supported_languages.txt` (currently force-added). `*.exe`/`*.zip` hide
  required local sources. This needs rewriting before any Deb work.
- **AUR sync.** Use `.SRCINFO` generation + a publish script (e.g.
  aurpublish/git subtree) so the repo and the AUR stop diverging in both
  directions.
- **CI (GitHub Actions):** shellcheck on launchers, `makepkg --printsrcinfo`
  + `--verifysource` on non-interactive packages, namcap,
  `desktop-file-validate`, `rpmspec -P` + rpmlint, lintian, and nvchecker
  for upstream bumps (which would have caught tributary, ageLANServer, owntone, ut2004).
- **Metadata hygiene:** SPDX licenses (`GPL` → `GPL-2.0-or-later`,
  `custom` → `LicenseRef-…`), one Maintainer format, drop `i686` from every
  wine/x86_64-only package, icons to `hicolor/<size>/apps` instead of
  `pixmaps`, drop the invalid `Application` desktop category, quote every
  `$pkgdir`/`$srcdir`, and use `install -Dm644 -t` instead of `cp -r` +
  `mkdir`. Replace `.install` echo banners with `README` docs (RPM and Deb
  discourage `%post` output).

## 6. AoE/AoM LAN play (implemented 2026-11-02)

ageLANServer is now one shared package instead of being bundled into each
game:

- `agelanserver-bin`: upstream's launcher, server and Battle Server manager in
  read-only `/usr/lib/agelanserver`, plus `agelan <game>`, which renders the
  launcher/Battle Server manager configs for every run (no stale per-user
  copies) and starts the game through gamelaunch. Only a user who hosts
  gets a per-user server copy (the server keeps certificates next to its
  binary). `agelanserver@<game>.service` hosts as a system service with
  `CAP_NET_BIND_SERVICE` and a bind-mounted certificate directory, the same
  layout upstream's Docker image uses.
- `agelanserver-companion-bin`: the companion DLLs, linked by each game into
  `steam_settings/load_dlls/` (gbe-fork-bin experimental build).
- The games keep a small descriptor (`/usr/share/agelanserver/games/<id>.conf`)
  and a `<id>-lan` menu entry.
